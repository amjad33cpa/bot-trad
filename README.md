# US Market Sentinel — بوت تنبيهات الأسهم الأمريكية

نسخة أولى للتجربة والبحث، ترصد قائمة أسهم تلقائيًا وترسل تنبيهات عربية إلى تلقرام مع نطاق دخول، هدفين، وقف خسارة، ومتابعة الخروج. لا تحتاج إرسال طلب لكل سهم. لا تنفّذ أوامر لدى وسيط، ولا تدّعي ربحًا أو دقة مثبتة.

**الإعداد الافتراضي الذي طلبته:** `MODE=paper` وبيانات `IEX` المجانية، والجلسة الليلية متوقفة. تشغيل البرنامج باستمرار يختلف عن توفر بيانات تداول طوال اليوم. هذه النسخة المجانية ترصد الجلسة الرئيسية فقط؛ IEX مصدر جزئي من السوق الأمريكي، وليس سعرًا موحدًا لكل البورصات.

## ما يعمل

- فحص تلقائي كل 30 ثانية لقائمة قابلة للتعديل، بحد 50 رمزًا، مع مؤشر SPY لفلترة اتجاه السوق.
- اختراق قمة آخر 20 دقيقة، EMA 9/21/50، توسع الحجم، VWAP متحرك داخل الجلسة، وATR.
- استخدام الشموع المكتملة فقط، والتحقق من تسلسل آخر 55 دقيقة، ومنع خلط بيانات الجلسات.
- رفض عروض الأسعار الأقدم من 20 ثانية، الأسعار المتقاطعة، السبريد الواسع، السيولة الضعيفة، ومطاردة السعر.
- إعادة فحص سعر الدخول قبيل الإرسال، وصلاحية دخول 60 ثانية، ومتابعة لا تتجاوز 90 دقيقة أو نهاية الجلسة.
- فلترة الجلسات وفق تقويم Alpaca، بما يشمل العطلات والتوقيت الصيفي والإغلاقات المبكرة. تبدأ الإشارات بعد اكتمال 55 دقيقة بيانات داخل كل جلسة؛ لا توجد استراتيجية افتتاح السوق في هذه النسخة.
- حفظ التنبيهات والنتائج في SQLite، وصندوق إرسال مستمر، ومنع التكرار والتزاحم بين عمليتين تستخدمان الملف نفسه.
- ذكاء اصطناعي محلي: تدريب مصنف Logistic Regression بأوزان JSON على نتائج التجربة، وفصل زمني للاختبار مع استبعاد النتائج المتداخلة عند الحد الزمني. لا اشتراك AI خارجي مطلوب.
- Docker، إعدادات خدمة Railway، وGitHub Actions للاختبارات.

## حدود يجب فهمها

الاستراتيجية والعتبات فرضية بحثية لم تُثبت ربحيتها. اختبارات الكود ببيانات اصطناعية لا تمثل اختبارًا تاريخيًا للسوق. لا يوجد نموذج مدرّب حقيقي مرفق، ويظهر «الذكاء الاصطناعي غير مفعّل» حتى جمع بيانات كافية وتدريب نموذج يقبل اختبار الفترة المحجوزة. درجة النموذج ليست احتمال نجاح معايرًا.

هذه خدمة polling: وصول التنبيه يعتمد على إغلاق شمعة الدقيقة ودورة الفحص والشبكة، وليس تنفيذًا فوريًا بالمللي ثانية. تتابع أسعار bid المرصودة، وقد يفوتها لمس هدف أو وقف بين دورتين. الانقطاع الأكبر من 90 ثانية يغلق المتابعة بنتيجة مجهولة مستبعدة من التدريب؛ لا يعيد اختلاق نتيجة من أسعار لاحقة.

لا توجد بيانات أرباح شركات أو تحليل أخبار أو تدفق أوامر/L2 أو كشف كامل لحالات تعليق التداول داخل الجلسة. أضف نوافذ الحظر يدويًا حول الأحداث المعروفة، ولا تعتمد على فلاتر السعر كبديل عن هذه البيانات. لا يوجد مسح لكل أسهم السوق أو اختبار تاريخي لعدة سنوات في هذه النسخة. المسح محصور في `WATCHLIST`.

## تجربة محلية بلا حسابات

تحتاج Python 3.12 أو أحدث. داخل مجلد المشروع:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m sentinel demo
```

الأمر `demo` يعرض رسالة اصطناعية ولا يتصل بـAlpaca أو تلقرام. ملف `examples/demo-alert.txt` مثال محفوظ للعرض.

## ربط تلقرام وAlpaca

1. أنشئ بوتًا عبر [BotFather](https://t.me/BotFather)، واحتفظ بالتوكن في Railway Variables فقط. افتح محادثة البوت واضغط Start.
2. استخدم معرف محادثتك الرقمي، أو أضف البوت مشرفًا إلى قناة خاصة/قناة ذات username واضبط `TELEGRAM_CHAT_ID` وفق ذلك. يمكن استخراج chat ID من استجابة `getUpdates` بعد إرسال رسالة للبوت؛ لا تلصق التوكن في روابط عامة أو في المستودع.
3. أنشئ مفاتيح حساب Alpaca Paper من حسابك المتاح لك، وأدخلها في `ALPACA_KEY` و`ALPACA_SECRET`. البرنامج يقرأ الأسعار والتقويم والأصول فقط، ولا يستخدم صلاحية إرسال أوامر.
4. أضف بقية المتغيرات من `.env.example`. الملف مثال فقط؛ البرنامج يقرأ بيئة التشغيل ولا يحمّل `.env` تلقائيًا.

## النشر على مستودعك وRailway

المستودع المستهدف: [amjad33cpa/bot-trad](https://github.com/amjad33cpa/bot-trad).

ارفع محتويات هذا المجلد إلى جذر المستودع بعد فحص المحتويات الموجودة، أو ادمجها في فرع جديد ثم راجع التغيير. لا تستبدل ملفات موجودة دون مراجعة، ولا ترفع ملفات `.env` أو قاعدة البيانات. ملف `.github/workflows/test.yml` يشغّل الاختبارات تلقائيًا.

في Railway:

يمكن نشر الخدمة أولًا مع `MODE=setup`: يعمل فحص `/health`، ويعلن `/ready` أن التنبيهات متوقفة دون إرسال رسائل أو طلب بيانات. بعد تجهيز Volume والمفاتيح، غيّر `MODE` إلى `paper` وأعد النشر. ظهور Deployment ناجح في setup لا يعني أن الماسح بدأ العمل.

1. اختر مشروعك ثم خدمة من GitHub وحدد المستودع والفرع الذي يحتوي الكود. إذا كانت الملفات تحت مجلد فرعي فاضبط Root Directory عليه.
2. أضف **Volume دائمًا** إلى هذه الخدمة بمسار `/data`. حجم 0.5GB مناسب كبداية للتجربة الصغيرة مع متابعة نمو السجل.
3. في Variables أدخل:

```dotenv
MODE=paper
ALPACA_KEY=<secret>
ALPACA_SECRET=<secret>
ALPACA_TRADING_URL=https://paper-api.alpaca.markets
DAY_FEED=iex
ENABLE_OVERNIGHT=false
TELEGRAM_BOT_TOKEN=<secret>
TELEGRAM_CHAT_ID=<your-chat-id>
DATABASE_PATH=/data/sentinel.sqlite3
MODEL_PATH=/data/model.json
AI_REQUIRED=false
```

4. اترك نسخة تشغيل واحدة ومنطقة واحدة، وعطّل Serverless/App Sleeping إن كان مفعّلًا. لا تضبط Cron؛ الخدمة حلقة مستمرة.
5. انشر Dockerfile. يقرأ السيرفر `PORT` تلقائيًا. اضبط Healthcheck Path إلى `/health` وHealthcheck Timeout إلى 120 ثانية وRestart Policy إلى On Failure بحد 10 محاولات. أمر البدء `python -m sentinel`.
6. أنشئ Domain للخدمة عند الحاجة لمراقبة `/health` و`/ready`. الأول يختبر حياة العامل، والثاني نجاح آخر دورة. لا تحتوي الاستجابات مفاتيح أو أوامر تحكم.
7. راقب السجلات أثناء جلسة السوق. ظهور `running` لا يعني أن فرصة مؤهلة موجودة؛ الفلاتر قد تمنع جميع الإشارات. راجع وصول أول تنبيه تجريبي بالفعل قبل الاعتماد على الخدمة.

تم ضبط هذه الإعدادات مباشرةً للخدمة الحالية. لا يوجد `railway.json`: أفادت واجهة Railway الحالية بأن Config as Code قد أُهمل للخدمات الجديدة، وبديله Infrastructure as Code. لتوثيق البنية محليًا لاحقًا، استورد إعدادات المشروع باستخدام `railway config pull` بعد تسجيل الدخول، ثم راجع أي خطة قبل تطبيقها. [المرجع الحالي](https://docs.railway.com/infrastructure-as-code).

Railway ليس ضمانًا لاستضافة مجانية مستمرة: بحسب وثائقه التي روجعت في 2026-09-23، التجربة حتى 30 يومًا أو استنفاد الرصيد، ثم خطة Free برصيد شهري محدود. لا توجد عملية شراء أو ترقية تلقائية في هذا المشروع. [الخطط](https://docs.railway.com/pricing/plans) و[التجربة](https://docs.railway.com/pricing/free-trial).

## حدود المخاطر الافتراضية

| الإعداد | الافتراضي | المعنى |
|---|---:|---|
| PAPER_EQUITY | 10000 دولار | رأس مال افتراضي لحساب الحجم، لا يقرأ حسابك الحقيقي |
| RISK_FRACTION | 0.0025 | 0.25% كحد أقصى للمخاطرة السعرية المخططة للفكرة |
| MAX_ACTIVE | 3 | أقصى أفكار تحت المتابعة |
| MAX_ALERTS_PER_DAY | 5 | أقصى أفكار مسجلة في يوم التداول |
| MAX_DAILY_LOSS_R | 2 | توقف الإشارات الجديدة بعد خسائر افتراضية تراكمية 2R |
| حصة السهم | 20% | أقصى قيمة اسمية افتراضية للسهم |
| إعادة السهم | ساعتان | فترة تهدئة، مع منع فكرة ثانية أثناء المتابعة |

الحجم محسوب عند أعلى نطاق الدخول والوقف. الفجوات والانزلاق والتكاليف يمكن أن تتجاوز المخاطرة المخططة. حد 2R يراقب النتائج الافتراضية المرصودة، وليس خسائر حساب الوسيط. النتيجة المجهولة تحسب 1R ضمن حد الخسائر تحفظًا. رأس المال الافتراضي ثابت ولا يمثل منحنى حساب أو عائدًا فعليًا.

الهدف الأول إشعار مراقبة فقط، دون افتراض بيع جزئي أو نقل تلقائي للوقف. الهدف النهائي 2.5R من السعر المرجعي؛ العائد مقابل المخاطرة عند أعلى نطاق الدخول أقل من ذلك. لا توجد إدارة تلقائية لمحفظة حقيقية أو تعديل أوامر لدى الوسيط.

## تشغيل الذكاء الاصطناعي

اترك `AI_REQUIRED=false` في مرحلة جمع البيانات، وبدون ملف نموذج. عند وجود ملف نموذج مقبول سيُطبق حتى في paper. لتجربة جمع جديدة غير منتقاة بالنموذج استخدم `MODEL_PATH` جديدًا غير موجود.

```bash
python -m sentinel export --database /data/sentinel.sqlite3 --output /data/observations.json
python -m sentinel train --input /data/observations.json --output /data/model.json --threshold 0.60
```

تنفذ الأوامر داخل بيئة تصل فعليًا إلى Volume أو على نسخة احتياطية محلية. `railway run` المحلي لا يمنح تلقائيًا وصولًا إلى `/data` البعيد.

التدريب يجمع كل مصدر بيانات وجلسة بصورة منفصلة. يحتاج على الأقل 300 نتيجة غير منتقاة مسبقًا بواسطة AI لكل مجموعة، منها 200 للتدريب و50 للاختبار، ويترك 90 دقيقة فاصلة إضافية بعد انتهاء نتائج التدريب. القبول البحثي يحتاج 30 عينة مختارة على الأقل في الاختبار، ودقة مرصودة 55% ومتوسط صافي R فوق 0.1. هذه حدود فحص أولي، وليست معيارًا علميًا كافيًا لإثبات ميزة تداول. الأسعار مرصودة كل دورة؛ النتائج ليست تعبئات حقيقية.

الاحتساب الافتراضي يبدأ من أعلى نطاق الدخول، وينتهي عند bid المرصود مع خصم 5 نقاط أساس إضافية لكل جانب. لا يختبر أعماق السوق أو أثر حجم أوامرك. أعد التشغيل لتحميل النموذج الجديد. صلاحية النموذج 30 يومًا؛ عند `AI_REQUIRED=true` غياب النموذج أو انتهاء صلاحيته يمنع الإشارات. يجب أن تتطابق `AI_MIN_SCORE` مع عتبة تقرير الاختبار؛ تغييرها يحتاج إعادة اختبار.

قبل أي استخدام بأموال حقيقية يلزم بيانات أوسع، واختبار زمني على فترات سوق مختلفة، وتجربة مستقلة لاحقة، ومقارنة تكاليف التنفيذ الفعلية. لا تسوّق درجات النموذج كنسب ربح مؤكدة.

## الترقية للجلسات الممتدة والليلية

عند الحصول على الاشتراك والصلاحيات المناسبة عند Alpaca، اضبط `DAY_FEED=sip` و`ENABLE_OVERNIGHT=true` مع إبقاء `MODE=paper` للاختبار. سيستخدم البرنامج SIP نهارًا وBOATS ليلًا دون الرجوع خفيةً إلى مصدر متأخر. ترفض الأخطاء/غياب الصلاحيات إنشاء تنبيهات جديدة.

الجلسات بتوقيت نيويورك: قبل السوق 04:00–09:30، الرئيسية 09:30–16:00، وبعد السوق 16:00–20:00، والليلية 20:00–04:00 ليوم التداول التالي، وفق العطلات وتوافر المصدر. في يوم الإغلاق المبكر نستخدم سياسة محافظة: إيقاف after بعد أربع ساعات من الإغلاق. الجلسة الليلية تتحقق من `attributes` للأصول وتستبعد `overnight_halted`. [مرجع 24/5](https://docs.alpaca.markets/us/docs/245-trading-for-trading-api) و[خصائص الأصول](https://docs.alpaca.markets/us/changelog/attributes-of-assets-api-endpoint).

`MODE=live` يغيّر وسم الرسائل فقط إلى فرص للمراجعة، ويشترط SIP و`AI_REQUIRED=true` ونموذجًا حديثًا مقبولًا. **لا يفعّل شراء أو بيع فعليًا**. لا يُقبل نموذج IEX لإشارات SIP أو BOATS.

## حظر الأحداث

الملف `config/blackouts.json` فارغ افتراضيًا. أضف بيانات موثقة بنفسك، مثال بنية فقط:

```json
[
  {"symbol": "AAPL", "start": "2026-10-01T12:00:00Z", "end": "2026-10-01T22:00:00Z", "reason": "Example only, not an actual earnings date"},
  {"symbol": "*", "start": "2026-10-02T12:00:00Z", "end": "2026-10-02T13:00:00Z", "reason": "Example market-wide blackout"}
]
```

غياب الملف أو خطأ بنيته يمنع دورة توليد الفرص؛ متابعة الأفكار الحالية تتم قبل قراءة الحظر. الحظر لا يعدّل الأفكار المفتوحة.

## التشغيل والصيانة

صندوق الإرسال يعيد المحاولة بتأخير متزايد. منع التكرار محلي ومستمر، لكن إذا قبل تلقرام الرسالة ثم انقطع الرد قبل تسجيل النجاح، يمكن تكرارها عند إعادة المحاولة؛ Telegram sendMessage لا يقدم مفتاح idempotency من طرف العميل. راجع رمز السهم ووقت الرصد لتمييز الفكرة.

سجلات البرنامج لا تطبع عناوين طلبات تحتوي التوكن. `/ready` يعيد 503 عند تعطل دورة البيانات/الإرسال. فحص Railway `/health` عند النشر ليس مراقبة مستمرة؛ يمكن إضافة مراقب خارجي لـ`/ready`. يوجد watchdog يعيد تشغيل العملية إذا علقت الدورة أكثر من 240 ثانية. تكرار فشل المزود يؤدي لخروج غير صفري لإتاحة إعادة التشغيل. فشل المفاتيح الدائم يحتاج تصحيحه يدويًا.

خذ نسخًا احتياطية من Volume. الإعداد الحالي نسخة واحدة وSQLite؛ ليس نظام توفر عالٍ متعدد المناطق. التنبيهات القديمة جدًا للدخول تنتهي بدل إرسال فرص فات وقتها. تحديثات الخروج المتأخرة تحمل وقت رصدها الأصلي.
